# data/synthetic — SYNTHETIC. Not government data. Never mix with `../processed`.

Everything in this directory is **generated by us**. No row here came from MPLADS, eSAKSHI,
MoSPI, or any government source. It describes works that do not exist, in districts that
were invented, with fraud labels planted by our own generator.

**If you are looking for real MPLADS data, you are in the wrong directory** — see
`../raw/` (real source) and `../processed/` (real, cleaned).

## Why it exists

Real MPLADS data has **no fraud labels**, so precision and recall cannot be measured on it.
This synthetic population has *known planted anomalies*, which is the only way to answer
"does the ranking machinery work?" Metrics computed here describe the **machinery**, never
the real world.

> Any metric derived from this directory must be labelled synthetic wherever it is shown.
> It is **not** a fraud rate, a detection rate, or an estimate of MPLADS irregularity.

## Contents

| File | Rows | What |

| `works.csv` | 406 | synthetic works, with an intentionally richer schema than reality offers |
| `events.csv` | ~2,900 | 7-stage lifecycle event log (`work_id, seq, event_type, timestamp`) |
| `ground_truth.csv` | 406 | `is_anomalous`, `anomaly_types` — the planted labels |
| `meta.json` | — | `"synthetic": true`, seed 3, thresholds, categories, anomaly tags |
| `photos/` | 40 | generated images for the perceptual-hash reuse demo |

## The schema here is deliberately richer than real data

`works.csv` contains fields that **do not exist in public MPLADS data**:
`expenditure_incurred`, `amount_released`, `progress_pct`, `vendor_id`, `sanction_date`,
`execution_start_date`, `first_payment_date`, `completion_photo_id`, `district`.

That is intentional — it lets the prototype demonstrate cost-overrun, payment and
photo-reuse detectors that **cannot run on real data**. Do not read this schema as evidence
that those fields are available; see `../README.md` §21.

## Who reads it

`mplads_audit/generate_data.py` (writes), `engine.py`, `photo_reuse.py`, `run_demo.py`.
`validate.py` builds its own in-memory synthetic population and does not read this directory.

**No file under `../processed/`, `../features/`, or `../outputs/` contains any row from
here.** The real pipeline (`load_real.py` onward) never opens this directory.

## Regenerating

```bash
python -m mplads_audit.generate_data     # -> works.csv, events.csv, ground_truth.csv, meta.json
python -m mplads_audit.photo_reuse       # -> photos/
```
